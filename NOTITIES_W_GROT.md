# NOTITIES_W_GROT: dungeons with a closed door, a dungeon window, queue + ready check (round W)

Branch `110-w-grot` from 0f00119f2 (110-v-int). The user's cheat sheet is `SPIEK_W_GROT.md`.

User request: "Caves hebben echt een dichte deur en een interface om de 'dungeon' te starten, te queuen met andere spelers etc."
Later the user decided on the wording: **the concept is "Dungeon"**. Caves are the first dungeon TYPE (`DungeonType.GROT`); outdoor
(BOVENGRONDS), building (GEBOUW) and flying-mount (LUCHT) dungeons come later and use the same system.

## What is built

### Generic dungeon system (`feature/vadsrijk/dungeon/`)
- `Dungeon` (interface) + `DungeonType` + `Dungeons` (registry with sources; `Dungeons.TEST` for gametests). A dungeon type implements
  `Dungeon` (id, type, name, subtitle, zone, levels, `bevat`, `bezig`, `reset`, `clears`, its own window lines, `pasAan` for its doors).
- `DungeonDeur`: the door block `guhs:vr_dungeondeur` (full, solid, unbreakable, no loot; property `thema`
  zwam/kristal/wortel/koraal/wolk/zout, `deel` 0 panel / 1 knocker / 2 hatch). It never opens. Right-click (also with a weapon in
  hand) opens the window. The game places the doors itself (first load of the chunk each session, re-checked every 30 s), ONLY in
  open cells (air, water, plants): nothing solid is replaced, no map regen.
- `DungeonDeurData` (GENERATED by `tools/features/vadsrijk_w_grot.py`): cells, stand spot in front (`voor`), spot inside (`binnen`).
- `DungeonRij`: instance per group, queue, ready check, cooldown, rules, exit, eject, dev commands, the window content.
- `DungeonNet` (S2C window state, C2S buttons) + `client/DungeonScherm` (pink panel in the Vadsrijk style, like QuestLopenScherm /
  RozeKnop; the game does not pause).

### The caves as dungeons (`grotkerker/`)
- `GrotDungeon` = a cave run as a `Dungeon` (type GROT). The boss, loot and rare-roll lines of the window live here.
- `GrotKerker` (u-grotkerker's run): the run only starts for the cave's group (`DungeonRij.lid` + `magStarten`), once per group; it
  scales with the group size (+ companions); the clear reports to `DungeonRij.klaar` (cooldown + "out through the door" + the
  window 3 s later). The gate board says "Dungeon uitgespeeld!" instead of "next run in". `grot run <id>` = a solo start through
  the door (dev, no rules); `grot reset <id>` also closes the group's instance; `grot baas` makes the dev the cave's group.

### The window (Dutch)
Title "Dungeon: De Zwamgrot", first line "Type: Grot · zone 1", advice "Aanbevolen: level 11-14 · 1-4 spelers (alleen goed te
doen)" (zone 3+: "2-4 spelers (alleen is pittig)"), "Eindbaas: Moeder Glimhoed" + subtitle, loot of every clear (coins 400·z²+300,
gear: first clear Episch / else Zeldzaam 12 % Episch, 3-5 ores, 25 % zone core), the personal rare rolls with pity, the SAME numbers
as `/guhs vadsrijk loot kansen` (pet 6 %, pity n/25; Pluimguh colour 10 %, pity n/15 or "pas als je een Pluimguh hebt" or "✔ al van
jou"), "Jij: N keer uitgespeeld", the cooldown, the status (vrij / bezet door een groep van n (m:ss) / jouw groep is binnen / jij
staat in de wachtrij n/4), buttons: Solo starten · Starten met groep (n) · In de wachtrij (or Uit de wachtrij + Nu starten (n/4)),
for members: Terug naar binnen / Dungeon verlaten / Nog even blijven. Tooltips on the start buttons.

### Queue + ready check
- Queue per dungeon, FIFO, matched in batches of **4** (`GROEP_MAX`). Players queued together as a party stay one block (w-party API).
- At 4, or when a queued player presses "Nu starten", the batch gets the ready check (30 s, "Klaar!" / "Nee", a time bar). All yes:
  everyone is teleported in together. A "no": no start, the decliners leave the queue, the rest stays. Time-out: the silent ones leave.
- The queue survives walking away; logout or a dimension change removes you. Action bar every 2 s: "Wachtrij dungeon De Zoutgrot 2/4".
- Party start: the leader presses "Starten met groep"; every online member gets the ready check (leader already yes).

### Server rules
- No start / queue while in another dungeon, in the raid (`Z6Raid.inGroep`), outside Het Vadsrijk, or with a cooldown for it.
- One group per dungeon (the instance). Anybody else found inside the cave box (survival/adventure) is put outside the door with a
  message; creative/spectator are left alone (dev).
- The door never opens for non-members: going in is ONLY a button; while the dungeon is taken the window says "Bezet".
- Exit: "Dungeon verlaten" (from the inside, or in the window after the clear) puts you on the stand spot OUTSIDE the cave box. Going
  in is never triggered by position, so the raid's old exit loop cannot happen; plus a 1 s grace on door clicks after coming out.
- End of an instance: no member inside (cave box or the stair between door and box, 24 blocks) for 60 s (10 s after a clear), or the
  last member left by the door. After a clear, if another group waits: "de dungeon gaat over 2:00 dicht", then members are put out.
- A member who fainted outside can use "Terug naar binnen".

## Decisions I made myself
- **Instance = a lock per dungeon**, not a copy: the caves are map terrain with U-GROTTEN's puzzle, treasure, craft spots and quest
  POIs (z6_s12 goes into the Zoutgrot) at fixed positions. Copying them per group would break all of that. Same model as the raid
  tower. A second group queues ("bezet").
- **Group size 4** for matchmaking (the pack scaling tops out at 4). A party may go in whole up to `Partijen.MAX` = 5.
- **Cooldown 10 min per player per dungeon after a clear** (replaces the shared 10-min "cave falls asleep"); saved in the player's
  `dungeon` data (`<id>.wachttijdTot`, wall-clock, survives restarts). Entering without clearing gives no cooldown (side quests
  that need the inside are never blocked for long).
- Made-up dev members ("Testguh n") never go in and do not count for scaling; companions (w-party) do count for scaling.
- The first room is NOT the teleport target: you arrive just behind the door and walk in (the run starts when you enter the box).
- The door is placed by the game, not baked into the tiles (no regen, cells only replace open blocks; the generator verifies it).
- Kristalgrot door 6 blocks into the tunnel; wolkengrot = a hatch; koraalgrot two doors.
- en_us copies the Dutch (round W brief).

## Parties (the user asked how they work)
- System: `kern/party/Partijen` (round 11). Max 5 players, a leader, not saved (a restart breaks parties up).
- Invite: chat command only: `/guhs vadsrijk party uitnodigen <speler>`, the other types `/guhs vadsrijk party accepteer`; leave with
  `/guhs vadsrijk party verlaat`. **There is no invite UI** (no menu tab); the HUD shows party frames (u-hud `PartyFrames`/`PartyHud`).
- XP share: every mob/boss kill gives the FULL xp to every party member in the same dimension within 48 blocks (`Spelers.geefXpGedeeld`,
  not divided). No friendly fire (no PvP in the dimension).
- Raid: on the start circle, party members standing in the Wachtzaal come along (`Z6Raid.metParty`), 2-10 players.
- Dungeons: "Starten met groep" = the leader's party (all online members, ready check); `DungeonRij.zetGroepInRij` queues a party as one block.

## API voor w-party
All in `nl.juiced.guhs.feature.vadsrijk.dungeon.DungeonRij` (public static), server thread only:
- **Queue a whole party**: `boolean zetGroepInRij(ServerPlayer leider, String dungeon)` - the leader's party (no party = just the
  leader), max `GROEP_MAX` (4); all members are checked (`weiger`); they are queued as ONE block (`BLOK`: member -> leader id) that
  matchmaking keeps together. Single player: `inRij(p, id)`; out: `uitRij(p)`; start early: `nuStarten(p)`; party direct start: the
  window's "groep" action (`actie(p, "groep", id)`).
- **Empty spots**: `int vrijePlekken(String dungeon)` (4 - queued, 0 while a ready check runs); `List<UUID> echteSpelersInRij(id)`;
  `int rijGrootte(id)`; `long wachtTicks(id)` = how long the queue is non-empty (-1 empty) for the "fill after ~1 min" rule.
- **Companions** (non-player): `record Metgezel(UUID id, String naam, String rol)`; `boolean voegMetgezelToe(String dungeon, Metgezel m)`
  fills a queue spot (auto "yes" in the ready check, shown by name in the check window); `haalMetgezelWeg(UUID)`. At the start the
  companions are passed to `BIJ_START` (spawn your entity there, next to `DungeonDeur.hoofd(id).binnen()`) and kept in
  `Instantie.metgezellen`. They get **no loot, no clear, no cooldown** (loot/clears only go to real players), but they DO count for
  the run's scaling (`groepsGrootte(id)`). The raid does not use this (no companions there).
- **"No NPC fill" flag**: `boolean geenNpcVulling(ServerPlayer p)` / `zetGeenNpcVulling(p, boolean)` (saved in the player's `dungeon`
  data, key `geenNpc`). Do not fill a queue where any queued real player has it set.
- **Events** (add-only lists):
  - `BIJ_CHECK.add((dungeon, leden, antwoord, allemaal, uitRij) -> ...)`: a ready check ended (all yes or not);
  - `BIJ_START.add((instantie, spelers, metgezellen) -> ...)`: a group went in (players are already teleported);
  - `BIJ_EINDE.add(instantie -> ...)`: the instance closed (despawn companions here).
- Queries: `instantie(id)`, `dungeonVan(UUID)`, `rijVan(UUID)`, `lid(p, id)`, `wachttijd(p, id)`, `Dungeons.alle()/van(id)`.
- A new dungeon type: implement `Dungeon`, register `Dungeons.bron(() -> list)`, add its doors to the generator (or `DungeonDeur.TEST`
  style data), start its run only when `magStarten(id)` and a member is inside, call `gestart(id)`, report `klaar(sl, id, players)`,
  call `runGereset(id)` when an unfinished run resets.
